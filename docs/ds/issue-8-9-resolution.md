## Card contract for #12

- Element: `wk-card`, a Wakata presentational primitive. It does not extend
  Lion. It has no implicit role, tab stop, click handler, navigation behavior,
  loading state or card-level event.
- Composition: a native heading element supplied in `slot="heading"`, default
  body content, and optional `slot="actions"`. The consumer chooses the heading
  level appropriate to the page. No heading level, landmark or accessible name
  is generated by the container. Body-only use is valid. Actions are ordinary
  independently named links/buttons and keep their own focus/activation.
- Appearance: flat `--wk-surface` background, `--wk-text` content,
  one-pixel `--wk-border` border and `--wk-radius` corners, with no shadow.
  Fixed starting geometry is 16px internal padding and 12px between occupied
  sections. The host controls width, outer spacing and layout. Do not add
  card-specific public spacing, elevation or click variants. #12's narrow,
  long-content and theme screenshots must verify this geometry; any visual
  correction needs a recorded review, not a silent token/API expansion.
- Wireframe keeps dimensions and semantic feedback colors. If a consumer puts
  images or logos inside, meaningful alt text remains theirs to provide;
  grayscale-logo and placeholder treatment is tested in #12's fixture without
  creating a media component family.

## Dialog contract for #13

- `wk-dialog` extends Lion's dialog path, with Lion's reflected `opened`
  property and public asynchronous `open()`/`close()` lifecycle. Use its public
  content and invoker slots. Require an accessible title on the content root;
  define description association in #13 using public APIs only. Do not expose
  arbitrary overlay configuration or private Lion members as Wakata API.
- The dialog is modal: contain keyboard focus, make background interaction
  unavailable and prevent background scrolling while open. Escape closes;
  backdrop interaction does not close in the initial contract. Initial focus
  goes to an explicit autofocus target if valid, otherwise the content root.
- On close, restore focus to the connected, enabled, visible invoker if the
  dialog still owns focus. If the invoker is gone or unavailable, focus the
  nearest surviving focusable ancestor of its original location; if there is
  none, temporarily focus the document's main landmark, then the body. Do not
  steal focus if the application already moved it outside the dialog. #13 must
  prove the fallback for Escape, programmatic close and removed content.
- A global overlay must use the origin's effective `data-wk-theme`,
  `data-wk-mode` and `data-wk-wireframe` and resolved supported `--wk-*` token
  values, including typography and public overrides. Update these while open
  when an origin/ancestor theme, mode, wireframe, class or inline-style
  attribute changes or System mode changes. Test adjacent and nested roots.
  Changes to external stylesheets without a DOM or preference event are not a
  promised live-update signal. This is implementation work for #13, not a
  claim that Lion already supplies it.

## Shared System / Light / Dark contract for remaining #9 work

- Provide `wk-mode-switch` as a first-party supporting control, with a native
  radio group in a fieldset, legend "Colour mode" and choices System, Light and
  Dark. It is not another component family or a replacement for Storybook's
  toolbar. Use native radio keyboard behavior. Public `mode` accepts
  `system | light | dark` and defaults to `system`; reflect it as an attribute.
  User changes emit one bubbling, composed `wk-mode-change` event with
  `{ mode, resolvedMode }` (`resolvedMode` is `light | dark`); programmatic
  writes do not emit a user-change event.
- System is the default, follows `prefers-color-scheme` live and removes any
  stored override. Light and Dark set `data-wk-mode` on the document root and
  persist one site-wide override under `wakata:color-mode:v1`. If storage is
  unavailable, the current page keeps its in-memory choice. Multiple switch
  instances in the same document reflect the same choice. An
  explicit local `data-wk-mode` still overrides the document root for its
  subtree. No-JavaScript fallback and SSR/hydration guarantees are outside
  this provisional contract.
- #9 remains open until this actual control has a documented public entry,
  keyboard/label/state tests, persistence/system-change tests, and a real HTML
  example. Card/Dialog may use Storybook's toolbar to inspect modes during
  development, but cannot claim their shared-switching criterion complete
  until the first-party control is exercised. #14 carries the HTML, React and
  Angular integration and manual AT matrix; #20 carries release/reference
  coherence and final visual acceptance.
